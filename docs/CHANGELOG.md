# 更新日志

## 2026-06-25 (三次优化)

### 配偶头像重叠修复 + 降低全景图密度

- **配偶同环并排**：此前配偶被放在 `r + 40`（径向外移）但与本人同角度，导致头像重叠。改为夫妻在**同一圈层（同半径）**上按角度间隔并排，角度间隔由节点直径换算弧长得出，中间以红线连接，贴合示例。
- **角度间隔钳制**：配偶角度间隔限制在本人 wedge 的左半区内（留 10% 余量），保证多配偶/窄扇形下也不会侵入相邻家族的扇区。
- **配偶权重保障**：角度分配权重新增 `angularWeight()` —— 取「子树叶子数」与「1 + 同环配偶数」的较大者，确保有配偶的节点 wedge 足够宽，从源头杜绝拥挤。
- **中心配偶内环化**：中心人物的配偶由原 `60 + n*18` 的拥挤半径，改为固定内环 `RingWidth * 0.55`，清晰避开大尺寸的中心节点。
- **默认只显示 3 世**：`generationLimit` 默认值由 `5` 改为 `3`，一次展示的关系层数减少，画面更清爽；用户仍可手动切换到五世/全部。重置视图也同步为 3 世。
- **精简标签层级**：多行详情（姓名+关系+职业地点）仅在中心、焦点、第 1 环显示，第 2 环起只显示姓名，减少文字堆叠。

## 2026-06-25 (二次优化)

### 全景关系图布局重构 — 解决头像重叠

针对节点/头像重叠问题，将极坐标布局从「平均角度分配」重构为标准的**径向树布局 (radial tree layout)**：

- **子树叶子数权重**：新增 `computeLeafCount()` 递归统计每个节点子树的叶子数（配偶不计入向外角度）。
- **加权角度分配**：`assignAngles()` 与 `partitionSector()` 改为按子树叶子数比例分配角度宽度，子树大的分支获得更宽扇形，从根本上消除节点重叠。
- **顶层扇区按子树规模分配**：根节点的父母/配偶/子女/兄弟等分组，扇区宽度由「人数」改为「叶子总数」，后代繁多的分支自动获得更大空间。
- **节点尺寸均匀化**：外圈节点尺寸衰减放缓、下限提高（边框 ≥28px、节点 ≥22px），各环视觉更接近示例。
- **环间距递增**：外圈环间距随层级递增（`RingWidth + level×20`），缓解外圈拥挤；背景同心圆半径同步为累积值，与节点实际半径对齐。
- **显式层级追踪**：`assignAngles` 携带 `level` 参数并存入坐标，节点尺寸与背景圆基于真实层级而非半径估算，深层节点不再失真。

### 安全加固与数据完整性改进

#### 高优先级安全修复

- **审核批准权限加固**：在 `POST /admin/review-requests/{id}/approve` 中添加家族权限验证，防止审核者批准其他家族的审核请求，消除跨家族权限提升漏洞。

- **路径遍历防护增强**：
  - 修复照片访问端点 `/member-photos/{filename}` 的路径验证漏洞，使用 `is_relative_to()` 方法替代不安全的 `in target.parents` 检查。
  - 修复备份下载 `/admin/backups/{filename}/download` 和备份删除接口的路径遍历漏洞，防止攻击者通过 `../` 序列访问或删除任意文件。

#### 中优先级安全改进

- **Excel 公式注入防护**：在 Excel 导入的 `clean()` 函数中清理以 `=`, `+`, `-`, `@`, `\t`, `\r` 开头的单元格内容，防止恶意公式在导出的 Excel 文件中被执行。
- **密码强度增强**：密码验证规则升级为必须同时包含字母、数字和特殊字符（如 `!@#$%^&*` 等），原有只要求字母+数字的策略已废弃。环境变量 `ADMIN_PASSWORD` 启动校验也同步更新，不符合新规则的密码将导致启动失败。
- **失败登录审计日志**：在 `POST /auth/login` 接口中，所有失败的登录尝试现在都会记录到审计日志（`auth.login_failed`），包含用户名和 IP 地址，便于安全分析和异常检测。
- **输入长度验证**：
  - 在 `FamilyGroup` 模型中为关键字段添加数据库级别的 `max_length` 约束：`name`≤100、`surname`≤50、`site_title`≤200、`cover_kicker`≤100、`subtitle`≤200。
  - 在 `Member` 模型中为名称字段添加 100 字符上限：`name`、`former_name`、`courtesy_name`、`art_name`、`childhood_name`。
  - 在成员创建 `POST /members`、更新 `PUT /members/{id}` 和家族更新 `PUT /families/{id}` 接口中添加运行时长度校验，超出限制返回 `400 Bad Request`。
  - 在 Excel 导入流程中添加家族名称和成员名称的长度验证，超长数据会导致导入失败并返回明确的错误提示。
- **配偶关系竞态条件缓解**：在 `sync_member_spouse_links()` 函数中添加 `session.expire_all()` 和 `session.flush()` 调用，强制每次更新前从数据库读取最新状态并立即提交，减少并发更新导致配偶关系不对称的风险窗口。
- **登录限流内存优化**：
  - 将登录尝试记录上限从 10000 降低到 5000，减少潜在的内存耗尽攻击面。
  - 添加基于时间的定期清理机制：每 60 秒自动清理过期的登录失败记录，不再仅依赖于达到数量上限时才触发清理。
  - 在 `check_login_rate_limit()` 中引入全局时间戳追踪（`LOGIN_ATTEMPTS_LAST_PRUNE`），即使没有新的登录失败也会定期执行清理。

- **HttpOnly Cookie 认证会话**：重构鉴权体系，将 JWT Token 传输从前端 `localStorage` 标头迁移至 HttpOnly、SameSite=Lax 的 Session Cookie (`access_token`)，彻底防御 XSS 劫持 Token 漏洞。
