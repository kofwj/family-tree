# 文档索引（docs）

本目录用于沉淀家谱系统的结构设计、权限规则、阶段整改记录与提交日志。

建议使用顺序：

1. 先看 **结构类文档**，理解系统边界与字段规则
2. 再看 **P0 整改类文档**，了解这一轮具体做了什么
3. 最后看 **logs/** 下的压缩版说明，快速回顾提交与阶段备注

---

## 一、结构与规则类文档

### 1. `家谱系统信息架构图说明.md`
**用途：** 说明系统的整体信息架构与页面职责。  
**适合什么时候看：** 当你要判断一个功能该归属树、成员录还是设置页时。

核心内容：
- 三大子系统边界
- 页面职责划分
- 模块间跳转关系
- 信息架构总图

---

### 2. `家谱系统字段分层与权限矩阵.md`
**用途：** 定义成员字段分层、角色权限边界、审计与审核预留。  
**适合什么时候看：** 当你要改表单、权限、字段展示或审计逻辑时。

核心内容：
- 身份核心层
- 关系结构层
- 人物档案层
- 系统控制层
- 角色权限矩阵
- 审计重点

---

## 二、P0 整改分析与执行文档

### 3. `P0现状差距清单_v2_带文件级改动建议.md`
**用途：** 记录 P0 开始前后的真实差距，并指出文件级改动位置。  
**适合什么时候看：** 当你要回顾 P0 为什么这样改、具体改动依据是什么时。

核心内容：
- 当前已有
- 当前缺失
- 风险点
- 建议改动位置

---

### 4. `P0变更提交说明.md`
**用途：** 作为本轮 P0 的正式提交说明与阶段性变更记录。  
**适合什么时候看：** 当你要整理提交、汇报或做阶段总结时。

核心内容：
- 变更背景
- 本轮目标
- 涉及文件
- 核心改动
- 已完成验收
- 后续建议

---

## 三、日志归档（压缩版）

日志目录：`logs/`

### 5. `logs/2026-05-25-P0-提交说明-最终压缩版.md`
**用途：** 更短的提交说明，适合快速复制到 commit / PR / 更新记录中。

包含：
- 建议 commit 标题
- commit 正文精简版
- 简版说明

---

### 6. `logs/2026-05-25-P0-阶段备注-最终稿.md`
**用途：** 本轮 P0 的阶段备注最终稿，适合做里程碑记录或周报摘录。

包含：
- 本轮做了什么
- 验收结果
- 当前结论
- 下一步建议

---

### 7. `logs/2026-05-25-生卒日期双轨并轨-阶段日志.md`
**用途：** 记录出生日期、去世日期从单一阳历字段升级为“阳历 / 阴历 / 原始记载”双轨并轨的阶段日志。

包含：
- 后端新增字段与 SQLite 自动迁移
- 前端表单录入改造
- 成员详情生命轨迹并轨展示
- 部署验证结果
- 后续日期换算与档案质量统计建议

## 六、维护建议

后续继续做 P1 / P2 时，建议保持同样模式：

- 结构文档放 `docs/`
- 阶段分析文档放 `docs/`
- 压缩版提交与阶段备注放 `docs/logs/`

建议命名规范：
- 阶段说明：`P1xxx.md`
- 差距清单：`P1现状差距清单_xxx.md`
- 日志归档：`logs/YYYY-MM-DD-阶段名-用途.md`

这样后面查找和回溯会很清楚。
